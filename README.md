# Invella

Рабочий сайт: https://invella.ru/  
Управление: https://invella.ru/admin.html  
Репозиторий: https://github.com/kattestgai-bot/Invella

HTML/CSS/JavaScript, Vercel Functions, Supabase Auth/Postgres/Storage и ЮKassa. Аккаунты, сохранения и оплата используют сервер и базу данных. Открытие HTML через `file://` не заменяет работающий сервер.

## Изменения от 27 октября 2026

Главная страница содержит своё оформление и ранние обработчики основных кнопок. Вход, регистрация и запрос восстановления работают независимо от SDK и редактора через тот же Supabase Auth. Результат входа сохраняется в существующем формате сессии SDK; пароль не сохраняется. Начальный сжатый документ главной и админки меньше 16 КиБ. Редактор и его код загружаются отдельно; резервный путь использует сжатые ответы меньше 6 КиБ (22 запроса для современной главной страницы). Старые страницы с ответами меньше 1 КиБ совместимы. Проверяются версия и целостность. Параметр delivery=small принудительно включает резервную доставку модулей; после успеха зеркала данные читаются напрямую из того же Supabase. Наличие такого режима не доказывает, что причина проблемы у пользователя — именно ограничение размера. Аналитика не нужна для запуска кнопок.

После подтверждённого на ноутбуке `styles/timeout` добавлен второй путь доставки публичных модулей — `invella-assets` на существующем Supabase. Его GET-запросы используют отдельный домен, проверку версии/частей и общий лимит двух одновременных передач. При недоступности зеркала остаётся исходный маршрут. Зеркало передаёт только семь разрешённых публичных файлов: оно не читает базу и не получает cookies/JWT клиента. После успешной доставки через зеркало запросы аккаунта и медиа идут напрямую в тот же Supabase с обычным JWT пользователя; формат сессии и RLS сохраняются. Записи не повторяются автоматически через другой маршрут. Платёжные запросы остаются на исходном сервере.

Сохранения выполняются последовательно. Переход из редактора ждёт сохранения; при ошибке переход блокируется. Операция закреплена за владельцем и приглашением. В редакторе есть статус сохранения и повтор. Локальные текстовые черновики разделены по аккаунтам. Повторный выбор медиа во время загрузки не стирает новый файл.

Подтверждение платежа записывает оплату, выдаёт тариф и учитывает промокод одной транзакцией. Повторное уведомление не создаёт вторую оплату, не понижает тариф и не включает отключённую администратором публикацию. При повторе одного перехода к оплате используется тот же ключ операции ЮKassa. Тестовые платежи отклоняются рабочими платёжными обработчиками.

После подтверждённой оплаты показываются благодарность, инструкция и переходы к приглашению, редактору и личному кабинету. Ожидание подтверждения и ошибка проверки имеют отдельные сообщения.

## Исходники и сборка

| Путь | Назначение |
|---|---|
| `src/index.html`, `src/admin.html` | Исходные страницы |
| `assets/invella-bundle.css` | Основное оформление |
| `assets/invella-app.js` | Авторизация, редактор, сохранения, гостевая страница, оплата |
| `assets/invella-premium-fix.js` | Файлы, музыка, галерея, таймер, предпросмотр |
| `assets/invella-early.js`, `assets/invella-shell.js` | Основные кнопки до загрузки редактора, диагностика начала ответа и резервная передача |
| `assets/invella-auth.js` | Независимая форма входа и передача сессии основному приложению |
| `supabase/functions/invella-assets/` | Резервная доставка разрешённых публичных файлов с другого домена |
| `scripts/delivery.cjs` | Сборка небольшой начальной страницы и отдельных модулей |
| `assets/invella-network.js` | Таймаут до получения всего ответа и резервное чтение через POST |
| `api/`, `lib/` | Серверные обработчики |
| `supabase/functions/` | Исходники четырёх действующих Edge Functions |
| `supabase/migrations/` | Изменения базы, уже внесённые в рабочий проект |
| `supabase/schema-snapshot.sql` | Снимок схемы, политик и прав без данных клиентов |
| `tests/` | Автоматические проверки |
| `docs/verification-2026-10-27.md` | Результаты и границы проверки |

Нужен Node.js 24. Единственная зависимость сборки — Terser 5.51.2, закреплённая в package-lock.json. Минификация держит начальный документ ниже 16 КиБ gzip. В браузер дополнительные npm-пакеты не загружаются.

```sh
npm ci
npm test
npm run build
```

Сборка создаёт `public/` и обновляет корневые `index.html`/`admin.html`. Vercel публикует `public/` и серверные `api/`. Исходники, тесты и SQL не публикуются как статические страницы. Редактировать следует `src/` и `assets/`, затем запускать сборку.

Старые версии скриптов и разовые GitHub Actions в репозитории не входят в сборку. Они сохранены как история прежних изменений; актуальная проверка — `npm test` (15 наборов). `api/startup-assets.js` обслуживает резервную передачу и совместимость с закэшированными старыми страницами. При ошибке загрузки видны конкретный модуль, тип ошибки и HTTP-код; диагностический сервер принимает только фиксированные значения и не записывает email, пароли или токены.

## Серверные настройки

Рабочие переменные Vercel: `SUPABASE_SERVICE_ROLE_KEY`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`. Значения хранятся в настройках проекта и в исходники не включены. `YOOKASSA_TEST_SHOP_ID` и `YOOKASSA_TEST_SECRET_KEY` отделены от рабочего магазина. Временные тестовые обработчики удалены. Для разработки с настоящими API нужны Vercel Dev и разрешённый доступ к переменным проекта.

Проект Supabase: `lwanymjmbcstvggmhevx`. Публичный ключ в клиентском коде имеет тип publishable. Владелец записей определяется настоящим JWT клиента, политики RLS проверяют его в базе. Резервное чтение `/api/read-data` передаёт тот же JWT; service role для этого не используется.

Права администратора определяются таблицей `invella_admins`, а не только адресом почты. Ручная активация и отключение доступны через `/admin.html`. Аккаунт администратора может отличаться от клиентского аккаунта.

Файлы хранятся в публичном bucket `invitation-media` с префиксом идентификатора владельца. Рабочий предел bucket — 25 МиБ на файл; допустимы JPEG, PNG, WebP и настроенные аудиоформаты. Создание такого bucket и перенос самих файлов — отдельная операция при переносе в новый проект.

Снимок схемы предназначен для передачи проекта и подготовки пустого Supabase-проекта. Он не содержит пользователей Auth, файлов Storage, данных клиентов, ключей или параметров SMTP. Не запускать его поверх существующих таблиц. На рабочей базе миграции этой поставки уже применены; повторный запуск не требуется.

## Что ещё не подтверждено

Автоматическая почта с инструкцией не подключена: в проекте нет настроенного сервиса отправки, подключённый доступ к управлению интеграциями Vercel возвращает 403. Для завершения нужен доступ владельца к подключению почтового сервиса и подтверждению отправителя. Пароли или секретные ключи в чат отправлять не нужно.

Автоматическая отправка чеков не подтверждена. Код не формирует фискальный чек; настройки отправки в рабочем магазине ЮKassa должны быть проверены владельцем. Возвраты обрабатываются вручную в ЮKassa; автоматическое изменение доступа по уведомлению о возврате не реализовано, доступ можно отключить в админке.

Финальная версия проверена в удалённом Chrome. Повторный ввод настоящего пароля, получение письма восстановления, вход администратора и новая реальная покупка в этой проверке не выполнялись. Предыдущая реальная оплата на 990 ₽ сохранена и проверена в базе. Для подтверждения устранения именно ноутбучного сбоя нужно одно открытие новой версии на этом ноутбуке; отчёт о запуске отправляется автоматически без email и пароля.
